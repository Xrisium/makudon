## 用户明确要求

1. 使用柔和卡片；正文试用 450，不支持时回退 400，UI 字体仍为 500。Noto Sans SC 的原始可变字体 `wght` 轴为 100–900，本次可真实使用 450。
2. 主界面底部为“目录 / 最近 / 设置”，启动默认进入“最近”。删除最近页的“文稿 / 在这里，继续写下去”标题口号。
3. 目录为简单层级树，支持常见排序；工具栏增加搜索与创建目录，展开 / 收起及排序按钮须有状态图标差分。
4. 最近页右上角以图标文字按钮“新建文稿”取代“本机”，进入二级页选择“纯文本 / Markdown / 导入”；不再使用新建卡片，最近文稿卡片不显示文件扩展名。
5. 正常编辑全自动保存，无常规手动保存按钮。
6. Markdown 支持源码与经过排版的两种视图，两种均可查看、编辑；名称尚待确认。
7. Markdown 文件类型使用微软 Fluent Markdown 图标，本轮选择原生 20px 版本；操作按钮保持 Lucide。
8. 文件和文件夹的长按菜单均提供“重命名”“删除”；删除前必须确认。

这些是整体产品方向，不构成实现授权。原首片仍先验证纯文本输入、可靠自动保存及最小文件出入口；完整目录和 Markdown 排版编辑需要后续独立实现方案，不自动并入首片。

## 最近与导航

- “最近”是跨目录的访问视图，不是存储目录。建议按最近打开 / 新建的时间倒序，纯阅读也能回到最近用过的文稿；不要让正在输入的稿件随每个按键反复重排列表。
- 新建入口位于右上角，与原“本机”标记采用相近的小字号、次级文字颜色和 Lucide 图标比例；可触区域仍至少 48dp。最近列表只显示文稿卡片，删除页标题不影响 TalkBack 的“最近”页面名称。
- 文稿卡片保留标题、短摘要、所属目录和类型 / 时间信息，隐藏 `.md` / `.txt`。相同标题可用目录与“Markdown / 纯文本”区分，实际类型和导出扩展名仍保留。
- 底栏只出现在三个主页面。新建、位置选择和编辑属于二级页面；编辑时收起底栏，返回来源主页面。
- 设置页可切换主题；分别显示 UI 字体与正文字体角色。450 / 400 / 500 是当前设计对照，不表示已实现正式字体管理。

## 目录树与新建建议

- 参考 [Obsidian 文件浏览器](https://obsidian.md/help/plugins/file-explorer)的层级、展开箭头、顶部新建 / 排序与文件夹上下文操作，收敛为适合手机的操作，不复制其工作区系统。
- 箭头负责展开 / 收起；短按文件夹名称选中目标。提示精确为“选择文件夹可更改新建位置，长按显示更多”，作为搜索框下方的一行普通次级文字，不使用图标、底色、容器边框或“当前：xx”路径。搜索关闭时提示仍位于工具栏与目录树之间。
- 删除目录中的新建位置 / 新建操作卡片和行末“…”入口。顶部“＋”使用选中的文件夹，长按文件夹可直接新建文稿 / 文件夹。仅展开文件夹不改变新建位置；选中行高亮保留，二级新建页仍明确显示完整目标。
- 无选中目标时使用文稿库根目录。新建页始终显示完整目标路径，点击可以更改；从选中的目录进入时不跳回默认位置。
- 排序建议包含名称、修改时间、创建时间、类型和 UTF-8 文件大小；可升 / 降序，默认名称自然升序、文件夹优先。
- 排序只在各自父目录的同级子项内进行，不把目录树摊平成文件列表。名称使用中文本地化比较与数字自然序；主键相同时用名称和稳定 ID 打破平局。
- 文件夹没有正文大小或文稿类型；涉及这些字段时，文件夹之间仍按名称排序。是否文件夹优先应显式可见；文件夹日期的生产定义还需另行确定，例图不伪造目录统计能力。
- 排序是显示偏好，不重命名、移动或重写文稿正文。

### 工具栏、菜单与状态图标

- 工具栏顺序为“搜索 / 排序 / 展开或收起全部 / 创建目录 / 新建文稿”，创建目录紧邻新建文稿左侧，搜索紧邻排序左侧。
- 五个按钮保持至少 48dp 热区；窄屏将按钮整组换到“目录”标题下方一行，不缩小热区或挤压标题。
- 全局展开 / 收起按钮使用 Lucide `unfold-vertical` / `fold-vertical`，根据当前可见树的展开情况切换动作；逐项按钮使用 `chevron-right` / `chevron-down`，文件夹本体同时用关闭 / 打开图标。
- 排序菜单采用与当前主题一致的不透明圆角浮层、轻描边与克制阴影；每项包含图标、名称和选中勾选，下方为升降序分段和“文件夹优先”。替换浏览器原生 select 的视觉示意，保留键盘方向导航、Escape 关闭及按钮焦点返回。

| 排序依据 | 工具栏图标差分（Lucide） |
| --- | --- |
| 名称 | `arrow-down-a-z` / `arrow-down-z-a` |
| 修改时间 | `clock-arrow-up` / `clock-arrow-down` |
| 创建时间 | `calendar-arrow-up` / `calendar-arrow-down` |
| 文件类型 | `file-type`，配独立升 / 降箭头标记 |
| 文件大小 | `arrow-down-narrow-wide` / `arrow-down-wide-narrow` |

- 图标之外仍使用明确的菜单文字和无障碍名称，例如“排序：修改时间，降序”，不能仅凭图形判断状态。
- 搜索例图按文稿名称（含类型后缀）在全部文稿中查找，展示所在目录，关闭后恢复原有目录展开和目标选择；没有全文搜索或磁盘索引实现。搜索范围及是否包含目录名为后续可讨论项。
- 创建目录例图显示父目录和名称输入，检查空名称、斜杠 / 控制字符 / 首尾空格及同父目录重名；创建后展开父路径并选中新目录。只改变预览内存，不执行磁盘 I/O 或真实目录迁移。
- Markdown 的 20px Fluent 类型标识使用[单个上游 SVG](../../assets/icons/fluent/markdown-20-filled.svg)，用于目录、搜索结果和新建页；[MIT 许可与固定来源](../third-party-assets.md)完整保留，不导入整个图标集。

### 长按条目菜单与剪贴板建议

2026-10-25 用户要求：长按文件 / 文件夹行显示类似右键菜单的浮层。普通短按行为不变，行末不再占用省略号按钮。目录行和名称搜索结果共用该菜单；桌面例图支持右键、菜单键 / Shift+F10，菜单支持方向键与 Escape。触控长按约 500ms，明显移动、滚动或 pointer cancel 取消识别；松手不能再触发短按打开。

| 条目 | 菜单动作 |
| --- | --- |
| 文件 | 更多信息、重命名、复制、剪切、粘贴、删除 |
| 文件夹 | 更多信息、重命名、复制、剪切、粘贴、新建文件夹、新建文稿、删除 |

- 信息页展示名称、类型、所在路径；文件另示 UTF-8 字节数、正文码点数和示例修改时间，文件夹显示直接子项数。以上不向日志或宿主状态输出正文。
- 文件夹菜单的粘贴目标是该文件夹；文件菜单的粘贴目标是其所在目录。菜单中说明目标或不可操作原因，空剪贴板时禁用粘贴。
- 复制生成独立 ID，文件夹递归复制子目录与文稿；剪贴板在复制时捕获示例快照，粘贴不修改原稿。重复粘贴生成独立副本，名称冲突自动追加“（副本）”“（副本 2）”，不覆盖原条目。
- 剪切只记录待移动的稳定条目 ID，原条目仍存在并弱化显示。成功粘贴后才改变 parent ID、清空剪切状态；保留文稿 ID 与正文。目标同名时阻止移动并保留源和待剪切状态；粘贴回原目录不移动。
- 不允许将文件夹复制 / 移动到自身或后代目录，不允许形成 parent ID 环。例图对文稿库根目录禁用复制 / 剪切，对内置收件箱禁用剪切；这是内置位置的保护建议，正式文件管理规则待实施时确认。
- 菜单浮层需限制在页面内，支持关闭后返回条目焦点。Android 正式实现需要 TalkBack 自定义动作等可发现入口，不能只依赖长按手势；本轮只验证浏览器键盘替代操作。
- 剪贴板仅存在预览私有内存，不访问系统剪贴板，不跨刷新保存，不写入宿主状态。真实复制、移动、并发、活动文稿保存屏障、持久元数据发布和失败恢复尚未设计完成 / 实现；当前不是磁盘文件管理器。

### 重命名与删除确认

2026-10-25 用户明确要求两类条目均支持重命名和删除，删除必须先确认。以下交互已加入内存例图，真实文件操作尚未实现。

- 重命名使用主题化圆角对话框，显示所在目录；预选原名称，支持 Enter 确认、Escape / 取消返回。空名称、`.` / `..`、斜杠、控制字符、首尾空格及同级同类型重名均阻止提交，保留输入并显示原因。
- 文件输入只编辑基本名称，`.md` / `.txt` 在输入框末端作为不可编辑的类型提示。重命名不改变稳定 ID、类型、父目录或正文；文件夹改名后子项 ID 不变，路径动态更新。最近卡片仍隐藏扩展名，待剪切条目仍可按 ID 完成移动。
- “删除”置于菜单末尾，与普通动作轻分隔，采用低饱和警示色和 Lucide `trash-2`；重命名使用 `pencil-line`。不能只以颜色区分危险动作。
- 删除先打开独立确认框，明确显示条目名称、类型后缀和所在目录；文件夹另说明递归包含的子文件夹数及文稿数。确认前不修改数据，默认焦点为“取消”；Escape / 取消保留原条目，背景不可操作，Tab 焦点限制在对话框内。点击背景不执行删除。
- 用户确认后才移除目标及其后代，更新目录与最近列表；删除选中目录时回到其仍存在的父目录。删除待剪切条目或其祖先会清空对应剪切状态，已经捕获的独立复制快照仍可粘贴；删除当前示例文稿时清理编辑缓冲与保存计时器，避免延迟反馈访问已删除条目。
- 根“文稿库”是虚拟集合，重命名 / 删除禁用并说明原因。例图中的收件箱可重命名 / 删除；保持其 ID 时从最近新建仍指向它，删除后从最近新建显式回退“文稿库”，在二级新建页显示目标。此默认位置失效处理是建议，尚未成为持久目录协议。
- 当前例图没有回收站或撤销删除，确认框明确提示“删除后无法恢复”。正式产品如增加恢复能力，应另行定义生命周期、保留期限与失败恢复，不由此例图默认承诺。
- 真实实现须协调保存队列与元数据提交，防止删除后旧保存任务重新创建文稿；确认目标用稳定 ID，执行前重新校验。失败不能显示成功，取消不得清除未保存输入。见[数据安全约定](../data-safety.md)。

## 从最近新建的默认位置建议

推荐初始提供固定 ID 的“收件箱”，而非根目录散落或隐式沿用上次目录；例图允许重命名 / 删除，删除后的回退见上节，正式规则待确认。

| 入口 | 建议默认目标 |
| --- | --- |
| 最近页右上角新建按钮 | 收件箱（保持 ID 可改名）；若已删除则显式回退根目录 |
| 目录顶部新建文稿 | 当前明确选中的目录；未选择时为根目录 |
| 文件夹菜单新建 | 该文件夹 |
| 新建页导入 | 新建页显示的目标 |
| 系统“打开方式”导入 | 收件箱，仍建立独立私有副本；本项为建议，待确认 |

- 不沿用隐藏的“上次浏览目录”；以后如提供用户可配置的默认新建目录，需显式设置、展示，并处理目标已删除的情况。
- 收件箱是应用内逻辑目录。目录组织建议用稳定目录 ID / parent ID 表达，正文继续由私有文稿 ID 定位，不因移动逻辑文件夹而覆盖另一篇正文；这只是后续存储设计方向，尚无迁移实现。
- 新建和导入都生成独立文稿 ID，显示名相同也不覆盖。复制 / 剪切 / 粘贴已加入内存交互例图；真实整理与移动的磁盘协议仍需单独设计，不能将示例当作已支持真实文件移动。

## 全自动保存

- 移除常规保存按钮和要求用户记得保存的流程；正文变化触发原有有界自动保存调度。
- 保留“等待自动保存 / 正在自动保存 / 已保存到本机 / 修改尚未保存”反馈。只有当前版本真正提交并校验成功才能显示已保存。
- 用户返回列表、切换文稿或切换主标签前，仍执行保存屏障；失败时留住当前编辑内容并显示重试 / 导出 / 继续编辑等出口。后台与进程死亡边界仍见首片规范。
- “重试”是异常处理，不是常规手动保存；导出不会清除主存储保存失败。
- 全自动保存不等于故障或系统强杀时未落盘文字零丢失。

## Markdown 模式命名与编辑边界

建议短名称为 **“源码 / 排版”**，辅助无障碍说明为“源码编辑 / 排版编辑”。“阅读 / 预览”容易暗示只读；“所见即所得”又容易承诺完整的富文本能力，因此暂不采用。

- 两种模式查看和修改同一篇 Markdown 源文；不是复制一份排版结果，也不是 HTML 与 Markdown 各存一个互相覆盖的正文。
- 无修改切换必须保持源文字节不变，包括空行、缩进、未知语法和末尾换行；模式切换本身不能触发格式化重写。
- 排版编辑需要把明确的局部编辑映射回源文相应范围，不可通过全量 HTML → Markdown 往返静默损坏原文。未支持的结构应保留原始片段并提供源码编辑入口，不宣称所有语法都可富文本修改。
- 模式切换应尽量保留对应光标、选区、滚动锚点及撤销会话，不能中断输入法组合；具体支持程度、语法范围、映射和撤销模型尚待技术验证。
- Markdown 初次打开暂以排版模式示意，是否记忆每稿上次模式尚待讨论；纯文本只提供直接文本编辑，不显示无意义的模式开关。
- 正式 Android 编辑引擎尚未选型；浏览器的 `contenteditable` 仅用于解释交互，不改变“不使用 WebView 编辑器”的产品约定。

## 本轮例图的实际能力与限制

- 可切换三个主标签、展开 / 收起目录、选择目标与排序，进入三选项新建页并创建内存示例，模拟导入独立副本；包含名称搜索、目录创建、排序浮层和长按条目的信息 / 内存复制 / 剪切 / 粘贴 / 重命名 / 删除确认。
- 默认最近、夜墨主题、正文 450、界面 500；保留其他候选主题及正文 400 / 500 对照。
- 示例 Markdown 的一级 / 二级标题和普通段落可在排版中编辑，也可在源码文本框编辑。复杂语法仅保留为原始片段；这不是完整 Markdown 编辑器，不能用于验证任意文稿往返保真。
- 自动保存反馈是计时器状态演示；没有磁盘提交、系统选择器、导出、跨会话保存或 Android 生命周期实现。
- 不将输入正文写入预览的宿主状态、日志或仓库。关闭 / 刷新例图会丢失输入；只用于合成文字试验。
