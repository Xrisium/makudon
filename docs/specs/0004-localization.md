## 2. 语言与资源约定

### 2.1 默认与匹配

目标为简体中文 `zh-Hans`、通用英文 `en`。默认跟随系统；应用内提供“跟随系统 / 简体中文 / English”。语言名称用自称，便于用户在陌生界面中找回自己的语言。

建议将完整英文放在无限定的 `values/`，将现有中文迁至 `values-b+zh+Hans/`。这样未匹配语言的资源有完整英文兜底，未来译者也有统一的英文源文。中文仍是首要产品验收语言，迁移需逐项保留现有措辞，不能用英文回译替代现有中文。

Android 根据配置中的语言列表、脚本、地区和现有资源选择最佳匹配；不要自己用 `startsWith("zh")` 将全部中文映射成简体。简体目标至少测试 `zh-Hans`、`zh-CN`、`zh-SG`；繁体 `zh-Hant` / `zh-TW` / `zh-HK` 作为未正式支持的匹配案例记录实际结果，不承诺统一强制回退英文，也不宣称已支持繁体。多语言系统列表仍交给 Android 解析。

不先创建空的日文、繁体或 RTL 资源目录。新增语言完成审核后才在正式语言声明和选择器中出现。

### 2.2 目标目录

```text
app/src/main/res/
  values/strings.xml                 完整英文源文、必要的 plurals
  values-b+zh+Hans/strings.xml        完整简体中文
  xml/locales_config.xml             正式支持的 en、zh-Hans
  raw/notice_*.txt                   原始版权与许可，不翻译替换
app/src/debug/res/values/strings.xml  Makudon Dev 覆盖
docs/localization/
  CONTRIBUTING.en.md                 英文贡献流程与初始术语表
```

沿用单个 strings.xml 和功能分组注释；253 个 key 尚不需要拆多个模块或引入资源生成框架。将来按功能拆 XML 文件只改变组织方式，不改变资源 key。

本项目优先手写小型 `LocaleConfig` 并由 Manifest 引用，明确只声明通过审核的语言，避免依赖库的译文被误计为应用完整支持。此次不同时启用自动 LocaleConfig 生成。语言选择器、贡献覆盖报告和验证以该声明为正式语言清单，禁止另建一份相互独立的运行时语言注册表。

`values/` 的英文不再复制到 `values-en/`。使用 `tools:locale="en"` 为工具标注源语言；它不替代 LocaleConfig。品牌及真正不需翻译的技术名称在默认资源中使用 `translatable="false"`，各翻译目录不复制这些 key。语言自称可由受控的不可翻译资源提供，勿散落于 Kotlin。

若未来启用资源语言过滤或 App Bundle 语言拆分，必须确保已声明语言在离线应用内切换时可用，并验证 debug 伪语言未被过滤；首轮不增加下载语言包行为。

## 3. 应用内选择与生命周期

### 3.1 推荐实现

为了让 API 26–32 与 API 33+ 都能在应用内选择语言，推荐使用 AndroidX AppCompat 的应用语言 API，调用 `AppCompatDelegate.setApplicationLocales`；“跟随系统”传空的 LocaleList。API 33+ 与系统的每应用语言保持同步，系统设置中也能选择。

Compose 宿主须迁为 AppCompatActivity，同时将 `values/` 和 `values-night/` 的宿主主题迁为兼容 AppCompat 的无 ActionBar 主题；Compose 的主题、颜色、edge-to-edge 和状态栏仍须回归。只改 Activity 父类并不构成完整接入。

当前没有 AppCompat 依赖。实施时从官方稳定版本中选择与现有工具链兼容的固定版本，集中写入版本目录；记录它的传递依赖和相同构建条件下 APK 增量，不能在方案阶段虚报大小。备选是仅跟随系统、API 33+ 使用系统应用语言，代价为旧版 Android 没有独立语言选择；不建议自行实现 Context 包装与整套语言引擎。

### 3.2 设置归属与无主线程 I/O

语言属于应用 / 安装级偏好，与文稿库解耦。不得写入目录索引、ZIP 或恢复快照，不能因切换文稿库、恢复或撤回而改变语言。

API 33+ 以系统应用语言设置为权威，启动和回到前台读取它；不得用旧内存或私有偏好反向覆盖用户在系统中修改的选择。

API 26–32 采用小型私有原子偏好文件，保存 `system` / `en` / `zh-Hans`，读写在 IO dispatcher。不要直接启用 AppCompat 的 `autoStoreLocales=true`：官方说明该选项会进行主线程阻塞读写，与本项目约定冲突。无需为了一个偏好引入数据库或通用设置框架。

旧系统冷启动流程为：Activity 建立最小启动等待界面 → IO 读取偏好 → 主线程应用 Locale → 配置稳定后装配工作区并处理外部 Intent。首次冷启可能多一次重建，等待界面不得提前创建库、生成默认名或消费导入请求；加载结果保存在进程级状态，重建不重复读盘或循环设置 Locale。此路径须用 API 26 / 32 原型验证，再接完整编辑流程。

旧系统主动切换时先异步原子保存，成功后在主线程调用 API；失败保留原选择并提供本地化重试提示。只写入允许的值，损坏偏好回退跟随系统并提示，不得因此停止文稿读取。API 33+ 不另写一份竞争的权威偏好。

若设备从旧系统升级到 API 33+，旧偏好只作一次迁移候选：系统已有显式语言时直接采用系统；系统返回空列表时不能分辨“用户主动跟随系统”和“尚未选择”，通过一次可跳过的选择让用户决定是否沿用旧语言，不能静默覆盖空列表。迁移完成标记同样在 IO 写入。

### 3.3 重建与数据安全

保留现有进程拥有的单一 WorkspaceViewModel、TextFieldState、保存单写者和编辑会话。语言切换不得调用工作区 reload / 整库恢复，也不能再创建一个保存者。不得通过声明 `configChanges` 或手动替换全局 Resources 来绕过重建。

- 应用内语言入口位于设置页；工作区有真实忙碌操作或恢复提交时禁止开始切换，避免重复点击与重建交错。
- 应用内主动切换前复用最新输入保存屏障；失败时保留旧语言和编辑缓冲，沿用重试 / 导出出口。
- 用户从系统改变语言不能被应用拦截。必须依靠现有进程会话、后台保存与重建恢复保护，不能假设会先经过应用内屏障。
- MainActivity 的导入 requestId、FileExchange 的等待请求、ActivityResult 回调及任务去重必须继续有效；重新装配 UI 不得重新发起文件选择器、重复导入或重复导出。
- 页面、搜索、展开、滚动、未提交的对话框输入和导航锁按既有状态所有权恢复；语言变更不当作新导航。重建后结束过期动画锁。
- 禁止缓存已经翻译的 UI 文本、Activity Context 或格式化器到长生命周期对象。资源 ID、业务状态与原始参数可保留，显示时按新配置解析。

配置重建能保留进程内输入，不等于进程死亡能恢复未落盘输入；继续遵循现有数据安全边界，不为语言功能承诺零丢失。

## 4. 字符串、复数与消息模型

### 4.1 Key 与译文

沿用现有语义 key；新 key 使用英文 snake_case，优先功能前缀与语义，如 `language_title`、`language_system`、`error_language_save`。不使用中文、数组下标或完整英文句子当 key。

相同措辞但不同含义可拆 key；只复用确实同义的“取消”等动作，不强求所有“打开”或“恢复”共用译文。不为规范命名而集中改名全部旧 key。

所有可见标题、正文、提示、Toast、错误、无障碍描述与自定义动作都纳入资源；装饰图标使用空描述避免重复朗读。用户名称、正文、第三方应用标签、许可原文不送入翻译函数。

源文上方为有歧义的 key 注释：使用页面、动词 / 名词、参数类型与含义、是否为数据名称、允许换行等。例如 `%1$s` 是用户文件名而非路径，`%2$d` 是递归文稿数而非直接子项数。界面空间问题优先修改布局，不能要求译者靠不自然缩写适配。

### 4.2 格式与复数

- 每条文案保持完整语义，不在 Kotlin 拼接句子的前半段、计数、单位和后半段；标点与占位符顺序由译文决定。
- 格式参数显式编号，如 `%1$s`、`%2$d`，允许目标语言调换顺序。禁止删参数、改类型、增加未声明参数；XML 转义和 Android 字符串转义分别验证。
- 单一数量决定语法的句子使用 `<plurals>` 与 `pluralStringResource` / `getQuantityString`，如字符数、已选项数和“删除 N 项？”；不要在 Kotlin 写 `count == 1` 来覆盖所有语言。
- 英文提供 `one`、`other`，简体中文至少 `other`；新增语言补齐该语言需要的类别。`zero` 不是所有语言在数值 0 时必然选中的类别，0 件特殊状态应显式设计。
- 复数选择传原始数量，显示参数也必须传入；避免只传 quantity 而漏 `%1$d` 的格式参数。
- 同一句含文件夹数与文稿数时，不能用其中一个数控制两个名词。优先采用完整资源中的“Folders: %1$d; documents: %2$d”式独立标签。确需完整屈折句式时，使用 API 26 已有的 ICU MessageFormat；格式化仅在 feature 层集中处理，并单独验证 ICU 模式，禁止把 ICU 参数当 printf 参数检查。
- 初期不使用 HTML 承载普通文案；确需样式时保持完整句子并用可控注解。URL、扩展名、MIME、JSON / properties key、枚举存储值不翻译。

### 4.3 状态与错误

延续 `Failure → R.string`、备份阶段 → 资源的已有映射。仅对确实携带动态参数的消息增加小型 feature 层消息类型，例如“下载已保存 + 文件名”；不要创建跨层通用翻译 DSL。

`FileExchangeUi.message` 从解析后的字符串改为资源与原始参数，Compose 每次用当前 Context 解析。domain / data 不引用 R、Resources 或 Context，也不直接提供面向用户的中文 / 英文异常。异常技术详情不能代替本地化说明，日志继续禁止输出正文和私人路径。

API 32 及以下 Application Context 不能假定拥有 AppCompatActivity 的语言。把当前有效语言解析出的默认名称 / 命名参数按操作快照传入协调层，不能长期缓存 localized Context。API 33+ 同样保持这一边界，避免分出两套业务逻辑。

## 5. 内容、名称和格式

### 5.1 名称是数据

已有文稿 / 文件夹 / 副本名称逐字保留，切换语言不批量重命名。`未命名文稿` / `Untitled document` 仅用于新建或导入缺名时；导入已有名称不能自动翻译。

文稿库根节点的屏幕标签与路径展示按稳定 root ID 渲染当前语言，不能把索引里已有的中文根名称当成唯一翻译来源，也不能在切语言时重写索引。

副本与恢复副本后缀采用创建时语言。向现有复制 / 恢复算法传入小型不可变命名参数，继续复用已有冲突循环、UTF-16 名称长度限制和代理对保护；格式化结果须通过名称安全校验，资源缺陷不能放行斜杠、控制字符或超长名。

导入 ZIP 校验、恢复预览、冲突选择、提交及导出重试使用同一命名快照；处理中切语言只更新界面标签，不重新生成预览中已确认的名称或已准备好的分享文件。再次开始新操作时才取新语言。

新 ZIP 建议显示名为中文 `Makudon-备份-20261102-153000.zip`、英文 `Makudon-backup-20261102-153000.zip`；时间戳使用固定 ASCII / Locale.ROOT，扩展名保持 `.zip`。恢复文件夹同理。文件名风格不参与 ZIP 协议识别；冲突始终生成独立名称。

### 5.2 日期、数字与排序

最近分组继续按系统时区的自然日计算，不因界面语言改变时间戳、时区或分组边界。相对词翻译为 Today / Yesterday / Two days ago；同年省略年，跨年带年；日期顺序交给 Locale，时刻继续尊重系统 12/24 小时设置。

UI 数字按有效应用配置格式化，字节 / KiB / MiB 标签通过资源表达；字节与码点上限的数值不变。备份协议、磁盘格式、ID、时间戳和哈希使用稳定、不依赖 Locale 的编码。不要用本地化数字作为文件路径或解析输入。

名称排序向现有自然排序传入有效 Locale / 比较器，保留数字片段自然顺序、文件夹优先、升降序及稳定 ID 兜底。切语言可改变显示顺序，不移动文件。名称冲突、路径匹配、扩展名识别、名称搜索不能悄悄改用 Collator 或依赖默认 Locale 的大小写转换；土耳其语 I/i 等情形列入回归，原有冲突与搜索语义保持独立。

格式化缓存至少按 Locale、时区、12/24 小时配置失效。现有字体页“进入时日期”继续固定该次预览时刻，重建只更新其显示语言，不偷换预览内容。

## 6. 布局、字体与无障碍

英文可比中文更长，按钮 / 卡片优先弹性高度、换行和响应式排布；破坏性确认、保存失败和备份模式说明不能省略关键信息。固定宽度和行数限制逐处检查，不通过缩小字号解决溢出。

统一 start / end 布局语义。返回 / 前进箭头按阅读方向镜像，品牌、Markdown 标识、文件操作等图标不能一律镜像；横滑导航方向需有明确 RTL 映射。文件名与路径混排使用显示层 bidi 隔离，不能把方向控制字符写回原始名称、剪贴板或导出路径。

简中与英文沿用现有字体及系统缺字回退，不因切语言更改用户的界面 / 正文字体偏好。固定中英文双语字体样文属于字形样本，应标注不翻译；标题和说明继续翻译。字号、粗细、重音符、emoji 与回退字形均须可见。

未来日文 / 繁体不能仅凭 Noto Sans SC “有字”就宣称地区字形正确；阿拉伯文、印地文等要验证连写、字形塑造、方向与系统回退。按实际语言需求决定字体策略，不预打包所有地区字库。英文命名采用官方字体名称，例如 LXGW WenKai；品牌与字体的法定名称由维护者确认。

许可标题、阅读导航及素材说明可翻译；随包的许可证、版权与署名原文完整保留。译注与原文明示分开，不用译文替换法定文本。

## 7. 贡献与质量流程

仓库内 XML 是唯一交付来源，直接 PR 即可贡献；首轮不要求 Weblate、Crowdin、API 密钥或登录外部平台。英文贡献指南提供定位、术语、参数规则和验收要求，将来接平台也只同步同一批资源，不产生第二份运行时目录。

流程：说明语言与审阅者 → 翻译 XML → 资源与构建检查 → 截图和母语审阅 → 正式声明语言。未完成译文可保留在 PR / 分支，通过 Android 英文回退辅助试译，但不得把缺译的语言加入正式列表来规避缺译检查。

已发布的每种语言应覆盖全部可译 key；新增功能同时维护中英文。其他已发布语言的新 key 也须补齐，或在发布前明确调整支持范围，不能靠关闭 MissingTranslation 让混合语言版本发布。英文源文变更保留 key 时，PR 标出语义变化与需复核译文，不能把“key 存在”当作翻译仍正确。

翻译 PR 尽量只改资源与必要文档；新增语言声明由维护者在同一 PR 完成，必要的构建 / 语言选择改动单独说明。允许 AI 初译，但需要人工核对；保存失败、删除、覆盖、分享与备份等文案须有语言审阅记录，尤其不能把“已分享”译成“已保存”。

### 7.1 自动检查目标

现已通过 `LocalizationResourcesTest` 接入现有本地 Check 和 GitHub JVM 测试入口，无单独 Gradle 任务或额外全局工具。准确命令与检查边界见[贡献指南](../localization/CONTRIBUTING.en.md)；下列为设计目标，实际实现与未覆盖项以[本轮验证](../testing/2026-11-02-localization.md)为准。

检查至少覆盖：

1. XML 解析、重复 key、空值、默认资源完整性；正式 LocaleConfig 与翻译目录对应。
2. 缺译 / 多余 key、翻译目录覆盖不可译 key、资源类型不一致；新增语言复数类别与默认英文不必完全一致。debug 对 `app_name` 的已知构建覆盖单独允许，不能被误报为译文覆盖。
3. printf 参数的编号、类型和出现约束；plurals 各分支参数；如出现 ICU 模式则走专门解析与参数校验。
4. 翻译不得增加可执行标记或破坏换行 / 占位符；新语言不能用与源文完全相同率作为机械拒绝条件，因为品牌、技术词可以相同。
5. 保留 Lint 的 MissingTranslation、ExtraTranslation、格式字符串与 RTL 相关检查；不创建全局 ignore / baseline 规避问题。

Kotlin 硬编码的扫描作为审查辅助：不能因字符串没有汉字就认定英文硬编码合法，也不能把 Markdown 符号、测试夹具或技术常量一律判错。自定义扫描若有例外，必须局部说明用途。

### 7.2 需要实际执行的验收

| 层次 | 必须覆盖 | 通过判据 |
| --- | --- | --- |
| 构建 | `pwsh -NoProfile -File scripts/android.ps1 -Action Check`；测试 APK 编译 | 构建、实际 JVM 测试、严格 Lint 通过；记录数量与未运行项 |
| 资源 | 中英文全量、无效格式样例、缺 key 样例 | 校验能准确拒绝损坏资源，不只验证生产文件恰好通过 |
| 数量 | 0、1、2、5、11、21、100；双数量组合 | 复数分支与参数正确，无 `%1$d` 等裸格式符 |
| 平台 | API 26 / 32 / 33+；中英文系统与应用语言交叉 | 跟随 / 指定 / 重启恢复一致；系统设置和应用内设置不互相覆盖 |
| 配置 | en-US、en-GB、zh-CN、zh-SG、未支持语言、多语言列表、12/24 小时、跨年与时区变动 | 日期显示正确，原始数据不受影响，匹配结果有记录 |
| 编辑安全 | 等待保存时重建、保存失败、系统外部切语言、IME 组合、撤销、活动稿返回 | 正文与选区按既有能力保留，无旧保存覆盖、无重复写者；IME 真实体验保留人工验收项 |
| 文件与备份 | VIEW 冷 / 热启动、选择器等待中重建、导出重试、ZIP 预览 / 提交 | 导入不重复、请求身份稳定、名字快照固定、库与路径不被翻译 |
| UI 与可访问性 | 中英文所有页面 / 弹窗、320dp、200% 字号、深浅主题、TalkBack | 重要文案完整可读、动作可达、描述语言一致 |
| 扩展压力 | debug 伪本地化 en-XA / ar-XB；未来真实 RTL 语言 | 长文本、混排、图标与导航经截图和交互检查；伪语言不进入正式发布列表 |

现有 instrumentation 中依赖中文文本的定位需迁移为稳定语义 / 测试标识；验证翻译本身的断言另用对应语言预期资源，不能把所有断言改成恒等自身。优先增加能复现错误的行为测试，不为每条静态译文创建一条低价值单测。

先复用已装 AVD / SDK；缺少某版本时记录未覆盖，不自行安装整套环境。模拟器验证集中完成后依设备策略交付一个最终 APK；文档方案阶段不构建或安装。模拟器通过、APK 推送与真机人工体验分别记录。

## 8. 建议实施顺序与完成标准

1. **资源与边界**：迁移中文、补齐英文；修复复数、已翻译消息缓存、默认名 / 副本后缀与显示排序。先用系统语言验证两种语言，确保无存储协议迁移。
2. **语言选择**：验证 AppCompat 与异步旧系统偏好启动原型，随后接设置页、LocaleConfig、系统同步和重建；集中处理 Activity 主题与依赖差异。
3. **贡献与自动检查**：启用统一资源校验并接入本地 / CI，更新英文贡献指南中的真实命令；补语义变化与审阅记录要求。
4. **验收与交付**：执行上表并更新 status / roadmap；记录 APK 身份与实测依赖体积，按设备政策集中交付。

每个步骤保持可运行；构建系统、功能与文档依 Git 规范分开提交。用户已授权并实施本轮双语，长期实现选择记录于 [ADR 0009](../adr/0009-android-localization.md)；本文保留完整设计和验收目标，尚未覆盖的平台不能因功能接入而标为验收通过。

最终完成须同时具备：完整中英文、全版本预期语言行为、离线切换、编辑 / 导入 / ZIP 无数据回归、自动检查可拒绝资源缺陷、贡献者能按英文指南提交第三语言 PR。第三语言的实际翻译、完整 RTL 支持和发布商店多语言素材不属于本轮双语实现的默认范围。
