# 设计补充：本机文件导入与系统打开关联

- 日期：2026-10-24
- 状态：**已接入导入副本、窄范围 VIEW Manifest 与 `.txt` 导出，部分模拟器验收进行中。** 实际目录发布格式见 [ADR 0003](../adr/0003-workspace-catalog.md)，未覆盖兼容性见 [当前状态](../status.md)。以下保留初始设计约束，不将全部协议视为已完整验收。
- 依据：[D1 / D2 / D3 决定](0001-open-decisions.md)、[ADR 0002](../adr/0002-document-storage.md)、[首片设计](0001-plain-text-editor.md)。

## 1. 一致的副本语义

2026-10-31 更新：应用内文稿与 ZIP 选择先显示实际处理应用，优先排列已发现的华为文件管理；使用 GET_CONTENT / OPENABLE，并保留 OPEN_DOCUMENT 系统入口。导出增加只读分享和 API 29+ 下载目录保存，见 [ADR 0007](../adr/0007-file-manager-first.md)。下表系统选择器为后备路径，源文件与副本语义不变；本轮不增加外部 SEND 导入。

两种入口共用同一条导入链路：

1. 应用内“导入文件”：由系统选择器选择本机纯文本 / `.md`。
2. 文件管理器“打开方式 → Makudon”：接收系统 `ACTION_VIEW` 的文档 URI。

都只读源数据、校验并建立新的私有文稿，之后打开副本编辑。界面明确提示“已导入副本，修改不会影响原文件”；不申请源文档写权限、不覆盖源文件、不维护同步关系。即使对方额外授予写权限，也不使用它写回。

`.md` 首片按纯文本编辑，保留 Markdown 源码与文稿类型；不承诺语法高亮或渲染。最小出口固定为 `.txt` 导出，Markdown 语法字符不被剥离。

## 2. 文件选择与系统关联

| 入口 | 设计要求 |
| --- | --- |
| 应用内选择 | 先选择处理应用，`ACTION_GET_CONTENT` + `CATEGORY_OPENABLE`；系统后备用 `ACTION_OPEN_DOCUMENT`。单选、只读，`EXTRA_LOCAL_ONLY` 表达本机偏好；不遍历整个存储 |
| 系统打开方式 | 独立、窄范围的 `ACTION_VIEW` / `CATEGORY_DEFAULT` 接收入口，支持带读取授权的 `content://`，冷启动与已有会话转入使用同一处理逻辑 |
| MIME 优先范围 | `text/plain`、`text/markdown`、`text/x-markdown`；纯文本 MIME 或 `.txt` / `.md` 文件名提示都要经过实际内容检查 |
| 文件名不规范 | 可从 `OpenableColumns.DISPLAY_NAME` 获取显示名，不能假定 `content://.../123` 的 URI path 含扩展名或等于真实路径 |
| provider 未正确标注 MIME | 应用内可提供显式的“选择其他文件”通道，再限制为 `.txt` / `.md` 并严格校验；不能为关联功能全局注册 `*/*` 或泛化的 `application/octet-stream` 来接管全部二进制文件 |

Android 候选匹配受发送方 MIME / URI 和系统默认设置影响，不是桌面式的纯扩展名注册。真机上必须验证实际文件管理器的 `.txt` 与 `.md` 行为；如某管理器将 `.md` 错报为通用二进制且 URI 没有扩展名，记录兼容缺口，保留应用内导入路径，再按证据制定窄范围兼容方案，不能谎称所有管理器均已关联。

Makudon 可以成为候选，用户可在系统提供选项时选择“始终”；应用不替用户强制设置默认，也不把某台设备既有默认应用遮住选择器误判为未注册。首片不增加 Web 链接关联、`ACTION_SEND` 分享导入、`ACTION_EDIT` 原文件写回或批量文件导入。

`EXTRA_LOCAL_ONLY` 是选择器偏好，`content://` 本身不证明数据位于本机；应用不添加网络权限或主动抓取 HTTP 文件。首片承诺本机 provider 路径，云盘兼容另验。

官方依据：[SAF](https://developer.android.com/training/data-storage/shared/documents-files)、[Intent 匹配](https://developer.android.com/guide/components/intents-filters)、[MIME / URI 规则](https://developer.android.com/guide/topics/manifest/data-element)、[Intent 常量](https://developer.android.com/reference/android/content/Intent)。

## 3. 校验与导入结果

- 只通过 `ContentResolver` 读取授予权限的内容 URI；拒绝缺失 URI、无权限、目录、不可读流、未知外部 URI scheme。首片不把 `file://` 或传入字符串转换为应用私有文件路径。
- MIME、文件名和声明的大小都是提示，不能作为内容安全或完整性的证明；大小未知也必须执行有界流读取。
- 源文件读取最多 1 MiB + 1 字节以检测超限；绝不无限读到内存。严格 UTF-8，可识别并移除 UTF-8 BOM；不自动猜测 GBK / UTF-16，不用替代字符“修好”非法数据。
- 拒绝已识别二进制格式 / NUL 内容；UTF-8 可解码也不代表任何字节流都是受支持文本。接受中文、emoji、正常换行与制表符，不以 ASCII 比例误拒中文。
- 统一 CRLF / CR 为 LF，其余不 trim、不改缩进、不规范化 Unicode；空文件合法。校验原始输入大小、规范化后 UTF-8 大小以及码点数，正文必须同时满足 10 万码点与 1 MiB。
- 新文稿使用应用生成的不可预测、无路径语义 ID。源显示名只作显示元数据，清理路径分隔符 / 控制字符并限制长度；绝不据此决定私有写入路径。
- 重名与重复显式导入均创建新副本，以显示后缀区别，例如 `笔记（导入副本 2）`；不按同名、相同 URI 或相同内容自动覆盖旧稿。
- 本片不做编码选择器、目录递归、附件或图片导入。非法编码 / 二进制 / 超限均说明原因并保留源文件与当前文稿。

## 4. 导入提交与已有文稿保护

每次接收外部调用产生一个请求任务 ID，并在 Activity 重建的少量 saved state 中保留；恢复同一任务不能执行两次，新的真实 `onNewIntent` 调用则创建新任务。发布元数据记录 `importRequestId`（仅导入稿）以便提交后进程中断仍可核对该任务是否已经发布；不把正文放进 saved state。不能在没有调用方身份依据时宣称能识别任意外部重复投递，也不能永久按源 URI 去重。

1. 现有活动文稿若有未保存输入，先通过保存屏障；失败则保留原编辑会话，提示重试或取消此次打开，不直接换成外部文稿。
2. 读源流、限额解码和规范化都在 I/O / 后台工作执行；不因为候选组件已启动就显示“导入成功”。源 URI 若失去权限则报告失败，不假装已复制，不要求用户给全盘权限。
3. 在私有导入暂存目录为新 ID 写入正文与少量静态元数据，完成同步、完整回读校验后，再在同文件系统发布为正式文稿目录。
4. 发布前失败：原活动文稿与已有列表完全保留，半成品不成为可编辑正文；中断后暂存残片保留到可安全确认的清理步骤，不将它当作空的新稿覆盖。
5. 发布后即便进程在更新“最近打开”指针前死亡，新副本仍可通过扫描有效文稿目录重新出现。该指针只是 UI 提示，不能成为唯一文稿索引。
6. 在确认旧活动稿的最新版本仍已保存后再切换到新副本；若复制期间旧稿又被编辑，重新经过保存屏障。新副本可留在最小列表中，旧稿失败时不强制切页。

导入时复制的是这次读取到的内容，不提供源文件并发修改的事务快照保证。检测到读流失败或明显前后不一致时不发布并提示重试；成功后源文件继续改变也不影响私有副本。

## 5. 最小多文稿布局

原固定 `draft-v1/body.txt` 仅适合没有导入的单文稿草案，**尚无这类实现或需迁移数据**。更新后的设计为每篇独立目录，单时刻只编辑一篇：

```text
filesDir/documents/<document-id>/
  metadata.json     schemaVersion、id、显示名、kind、bodyFile、可选 importRequestId
  body.txt          plain 正文；markdown 时为 body.md（二选一）
  previous.txt      最近一次提交前的正文（存在时）
filesDir/import-staging/<request-id>/
  ...               导入初始化暂存，不作为正式文稿展示
```

元数据不包含正文或源 URI 的持久写回授权。`bodyFile` 只能为约定的 `body.txt` / `body.md`，与 kind 一致，读取时验证；不信任 JSON 中的任意路径。正文与 previous 各自按主设计提交，**自动保存不再同时重写静态元数据**，避免无必要的多文件一致性问题。

提供最小“文稿”列表用于重新打开已新建 / 导入的副本，展示名称与类型；可从目录扫描有效元数据得到，无数据库前置要求。首片不增加目录树、搜索、标签、排序配置、批量操作或删除。损坏目录应有可见错误入口，不静默遗忘文稿。

保存队列仍按文稿 ID 隔离、同文稿单写者；切换文稿时不能让旧稿的延迟回执改变新稿 UI 或把正文写到新稿路径。
