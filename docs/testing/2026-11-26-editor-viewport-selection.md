# 编辑视口、导航与选区修复

## 范围与根因

- 分支 `main`，任务 [0049](../tasks/0049-editor-viewport-selection.md)。无依赖、权限或工具链变化。
- 原连续输入框将上下 16dp padding 放在滚动框外；羽化再将该处画成纯色横条。纯文本两视图及 Markdown 源码 / 排版共用此路径，因此与 LazyColumn 阅读的边界不同。已将五视图视口直接衔接工具 / 信息行，去掉外部垂直 padding 与纯色条，并同步表格、图片、任务命中层的坐标。
- 排版由连续输入框进行源码投影，阅读为按块只读组合，结构区别来自 ADR 0011 的编辑 / 只读职责，不能简单互换渲染器。无序列表仅替换标记不会给续行缩进；阅读多个独立 Text 裁掉首尾行高会压紧项间距。现按当前字体测量标记宽度作悬挂缩进，并共享完整行高；相邻同级样式合并，使 LF 成为唯一项目换行，避免样式边界重复生成空段，源码不变。
- 导航覆盖层默认隐藏；隐藏触摸范围收在正文外侧 24dp 留白，明确纵向拖动才唤起。正文拖动及其惯性滚动在 800ms 窗口移动约 45% 视口后唤起，停止约 3 秒隐藏。程序位置恢复和光标自动滚动不参与唤起。
- 软换行行尾提供单独视觉亲和位置，使用下一行行首的同一偏移。输入、选区变化、组合输入、模式切换与失焦清除；布局变化时不得绘制过期坐标。

## 菜单来源与真机旧版复现

- 已检查当前 Compose Foundation 1.9.0 官方源码：默认文本菜单查询 Android `PROCESS_TEXT` 提供者，平台还可加入文本分类 / 厂商动作。LIO-AN00 当前系统报告 Android 12 / API 31，查询返回十个提供者，包含 Via 与 X 浏览器。设备实际原生菜单有“翻译”“AI 搜索”等，不能用此替代截图中 Harmony 安卓兼容层测试机的包来源核验。
- 只读提取 LIO-AN00 已安装的旧开发 APK，SHA-256 `60EBCA4B492DCB0FB009CD8A667E9DE4268E0FDB2FCA0D556B215A1D3B06C040`。该包在 API 36 模拟器出现纯文本阅读返回编辑后旧菜单残留；复现测试前五项通过，第六项菜单清理断言失败，不能记为通过。

- 新正文菜单使用公开 TextContextMenuProvider 与原生剪贴板回调，只呈现可用的剪切 / 复制 / 粘贴 / 全选；阅读无修改动作。系统分类及第三方文本处理入口均不呈现，包含 DeepSeek 和浏览器扩展。按钮按应用主题 / 字体居中，窄屏横向滚动；菜单与文稿 / 视图绑定，返回、切换、卸载时关闭，不再使用原生浮动 ActionMode 的旧坐标回调。
- 原始截图、目标进程堆栈、模拟器日志与旧 APK 均保存在忽略的 `.local/`，未重置真机文稿，未安装真机测试 APK。
