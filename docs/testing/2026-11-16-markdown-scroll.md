# Markdown 长文排版滚动优化

## 变更与测量方法

任务 [0043](../tasks/0043-markdown-scroll-performance.md)。在 `main` 保留连续 `TextFieldState`、源码投影及现有保存协议，无新依赖、权限或工具链变更。

原编辑器在组合阶段读取滚动像素，每帧重建全文投影、扫描表格 / 图片和任务框。现将滚动读取限制在导航和覆盖层，按正文 / 解析 / 选区缓存投影与图片缩进；任务目标缓存后按可见行二分定位，只查询可见任务的字符位置。

配置 AVD Android_API_36，API 36 / x86_64，1080×2400 / 420dpi；沿用模拟器原字体与主题偏好。仅操作模拟器中的独立合成稿，不重置文稿库 / 设置。测试后删除本次合成稿至既有回收站。

`markdown-scroll` 生成正好 100,000 Unicode 码点的中文 / emoji / 标题 / 粗斜体 / 链接 / 引用 / 任务密集文本，从顶端开始，Choreographer 连续四段各滚动 5,000px / 3 秒。记录主线程相邻回调的实际时间间隔，采样中不进行无障碍查询。系统动画倍率实际为 0，Choreographer 不依赖此倍率；未修改系统倍率。新旧总滚动范围均为 781,414px。

这是主线程滚动回调间隔，**不是 GPU 渲染耗时，也不是跨设备帧率基准**。系统 FrameMetrics 未返回样本，已弃用该采样方式；早期夹具监听器清理错误和文末光标问题已修正，其结果不计入比较。

## 同机比较

基线应用来自任务 0042 的已验证产物，SHA-256 `9A2C68CDBE9BC384644744E23567C881319D87514450A744D4E28DB224EB1469`。前后使用相同测试 APK、正文和滚动距离。每段独立统计，不将四个分位数再次当成整体分位数。原版每段仅产生 5–6 帧，表中 p95 只描述这些样本，不能视为稳定的性能分位数。

| 段 | 原版样本 / p50 / p95（ms） | 优化版样本 / p50 / p95（ms） |
| --- | --- | --- |
| 1 | 5 / 730.6 / 787.1 | 55 / 55.0 / 63.9 |
| 2 | 5 / 722.8 / 806.3 | 48 / 57.6 / 73.6 |
| 3 | 6 / 707.7 / 776.8 | 49 / 56.1 / 61.4 |
| 4 | 5 / 737.1 / 785.2 | 48 / 62.2 / 72.0 |

极端密集样本的连续滚动停顿明显减少，但优化版仍大量超过 32ms，不能宣称已稳定 60fps。连续全文输入组件的绘制、样式窗口变化及真机性能仍有后续优化空间。

本地原始输出与截图位于被忽略的 `.local/markdown-scroll/`；已查看排版长文截图，任务框、标题、链接及导航位置正常。
