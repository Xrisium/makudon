# 阅读视图选中与复制修复

用户反馈阅读模式无法选中文本，要求只锁定正文修改。实际分支 main，开始时工作区干净；修复不改变正文、保存协议、导航及羽化，无新增依赖或权限。

## 原因与修复

纯文本的只读 `BasicTextField` 仍会将长按 / 拖动选区交给 `InputTransformation`，原实现发现阅读模式便执行 `revertAllChanges()`，同时撤销选区。现先识别正文未改变的操作，保留选区更新；正文发生改变时继续执行全部模式 / 忙碌 / 存储状态门控。Markdown 阅读已有 `SelectionContainer`，本轮验证其实际选中与复制，不更换阅读实现。

## 验证

- 基线 APK 上用真实长按复现，纯文本选区仍折叠，专项第一个检查失败。修正版同一模拟器、同一文本能够长按拖动选中多个词并显示复制菜单。
- JDK 17 `Check -Offline` 通过，190 项 JVM 测试零失败 / 错误，严格 Lint 通过；最终测试 APK 构建与 Lint 通过。
- API 36 `reading-selection` 13 项通过，验证两类阅读视图实际触摸选择、复制到系统剪贴板、纯文本扩大选区后的精确复制、无剪切 / 粘贴菜单，以及尝试无障碍正文替换 / Delete 后全文与修订不变。已查看两类文稿的选区、手柄和复制菜单截图。
- `markdown` 33 项通过，覆盖跨段选择、共享撤销、中文 composing、只读门控和保存失败；`document-navigation` 28 项通过，覆盖阅读往返、实际拖动导航、左右布局、字号行距和重开 / 重建接续。本轮模拟器合计 74 项通过。模拟器只使用独立合成稿，测试后清理；原始输出和截图在忽略目录 `.local/reading-selection/`。
- 测试以实际尝试修改后的正文 / 修订判断只读，不能只用无障碍节点 `isEditable` 标记。只读输入框未提供设置选区的无障碍动作，扩大选区改用真实长按拖动验证。
