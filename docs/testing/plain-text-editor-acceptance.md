# 验收规范：首个可靠纯文本编辑切片

- 日期：2026-10-24
- 状态：**计划，所有用例均未执行；当前应用仍是占位页。**
- 依据：[设计方案](../specs/0001-plain-text-editor.md) 与 [导入 / 关联协议](../specs/0002-import-and-file-association.md)。私有目录、导入副本、文件关联和 `.txt` 导出均已确定。
- 文稿基线已确定为 10 万码点且 UTF-8 ≤ 1 MiB。按 [设备约定](../device-policy.md)，有真机连接时仅在真机运行验收，无真机才用模拟器，用户明确要求除外；当前已观察到 HUAWEI LIO-AN00 / API 31。

## 测试资料与证据

- 仅用合成文稿，包含中文段落、ASCII、emoji（含代理对 / 多码点组合）、组合字符、空行、缩进、制表符和末尾有 / 无换行的版本。
- 建立空文稿、小文稿、10 万 Unicode 码点且 ≤ 1 MiB 的长文、100 万码点压力文件；按码点与 UTF-8 字节两种指标记录，不能把 UTF-16 长度当作字数。
- 失败注入应限定本应用测试目录或替身：不要填满用户手机 / 系统磁盘、撤销其他应用权限或删除真实文稿。
- 每轮留存 Git 版本和本地差异、APK SHA256、设备 / API / 输入法、测试数据摘要、步骤、预期 / 实际、耗时与结果；按 [模板](../templates/manual-test.md) 记到里程碑记录。
- 正文一致性使用完整字节 / 摘要比较，不能只看截图里开头几行。运行日志只记录测试 ID、版本号、阶段和脱敏错误分类，不输出正文。

## A. 正常打开、编辑与保存

| ID | 步骤 | 必须结果 |
| --- | --- | --- |
| A01 | 启动进入最近列表并点新建，已有文稿时重复一次 | 不自动进入上次正文；每次生成独立 ID，空文稿初始化成功后才进入已保存状态；旧稿仍可从最小列表打开，初始化失败可见、可重试 |
| A02 | 输入包含中文 / emoji 的多段正文，停顿 | 停止输入 500 ms 后发起最新快照保存，状态顺序正确；完整回读一致 |
| A03 | 连续输入 10 s，不出现 500 ms 停顿 | 最早未覆盖修改的 2 s 期限仍发起保存，不被后续按键永远延迟 |
| A04 | 只移动光标、改变选区或滑动 | 不增加正文保存版本，不因这些动作轮换 previous |
| A05 | 粘贴 CRLF / CR、空行、缩进、无末尾换行文本 | 仅换行规范化为 LF，其他正文不改变；重开后字节一致 |
| A06 | 全选删除，等待保存，再重开 | 空文稿被当作合法内容；读取失败不会走同一空白分支 |
| A07 | 自动提交已捕获快照时又继续输入 | 无常规保存按钮；旧版本可完成，新版本未提交前不能显示整体已保存；正文和光标不回退 |
| A08 | 调度 / 生命周期重复请求保存同一内容 | 不制造无意义写入 / 恢复轮换，不改变正文或撤销历史 |

A02 / A03 的调度使用虚拟时钟验证；真机性能另按 E 组统计。不能通过人为延长等待来掩盖错误调度。

## B. 并发、失败与重试

| ID | 故障 / 竞态 | 必须结果 |
| --- | --- | --- |
| B01 | writer 人为延迟：写版本 10 时编辑出 11、12 | 同一文稿无并发写入；10 的回执不假报 12 已保存，最终最新内容为 12 |
| B02 | 数百次编辑和保存请求同时积压 | 最多一个执行中、一个最新待写；不堆积无限旧快照，不取消执行中文件事务 |
| B03 | 在 previous 写入 / sync 阶段抛异常 | 主正文完全不变；失败状态可见，当前新内容仍在编辑缓冲区 |
| B04 | 在主文件写入中途抛容量不足 / I/O 异常 | 主文件保留此前完整版本；无截断、乱码或空白替换 |
| B05 | 在 sync、提交、提交后回读分别注入失败 / 不一致 | 都不能假报已保存；回读不确定时停止破坏性写入并保留现场 |
| B06 | 保存失败后继续输入，再解除故障并点重试 | 不高速自动重试；新输入仍可编辑；重试写最新版本，旧回执不能清掉新错误 |
| B07 | 用慢加载模拟器，在读取返回前尝试输入 | 编辑尚未开放，不能产生空正文自动保存覆盖旧稿 |
| B08 | 空文本 / 空文件，与不存在 / 不可读 / 非法 UTF-8 分别加载 | 只有合法空文件是空正文；其余进入错误 / 恢复状态 |
| B09 | 重复打开 Activity、旋转或进入多窗口 | 不创建第二个独立 writer，不出现两个会话交替覆盖 |
| B10 | 失败时点离开或取消离开 | 保存失败时不会擅自关闭；重试 / 继续编辑 / 明确放弃有各自结果，无静默丢弃 |

B 组核心规则应有可重复的自动化测试；仅靠正常手动输入不足以验证并发与异常。

## C. 进程重建与恢复

| ID | 步骤 | 必须结果 |
| --- | --- | --- |
| C01 | 当前版本已显示已保存后，用 adb force-stop，再从图标启动 | 恢复该完整版本或更新的已提交版本；不靠 Bundle / ViewModel 残留通过测试 |
| C02 | 在 previous 提交后、主文件写入前结束进程 | 主稿仍为旧完整版本；previous 允许与它相同，不凭时间戳擅自替换 |
| C03 | 主文件只写部分字节时结束进程 | 重启恢复旧完整正文，不提升临时残片为最新主稿 |
| C04 | 主提交完成但 UI 未收回执时结束进程 | 重启能加载新完整版本，不按旧内存版本回滚 |
| C05 | 仅有初始化临时痕迹、或正文被测试故障模拟为缺失 | 不自动当新文稿覆盖；显示可理解恢复 / 重试路径 |
| C06 | 使主正文不可读 / 非法 UTF-8，previous 可读 | 停止自动保存，允许只读查看恢复副本；用户未确认前不覆盖主稿 |
| C07 | 用户确认恢复上一版本 | 先保存现场，恢复结果完整；保留原当前稿的独立材料，不把坏稿写进恢复副本 |
| C08 | 恢复现场复制失败或两份正文均不可读 | 不替换 / 删除原文件，不伪造空白成功，不承诺一定能恢复 |
| C09 | 输入后切 Home、锁屏、切应用，然后回来 | 尽早发起保存，队列不因页面停止收集而取消；失败状态仍可见 |
| C10 | 有未提交文字时突然 force-stop | 恢复最后完成提交的完整版本；未提交文字允许缺失，不把此项报告为“零丢字” |
| C11 | 横竖屏 / Activity 重建 | 正文、合法选区尽量保持，保存队列不被重置；系统“Don't keep activities”不能替代 C01–C04 的进程死亡测试 |

C02–C04 需要未来实现可控的测试阶段屏障，并在测试进程实际被结束后重启验证。测试钩子应限制在测试 / debug 构建，不添加产品界面上的故障按钮。单纯抛异常可以覆盖错误清理，但不能代替真实进程中断。

突然断电 / 文件系统损坏属于另一类设备测试，不在首片进程恢复结果中冒充通过。

## D. 输入体验与可访问性

| ID | 操作 | 必须结果 |
| --- | --- | --- |
| D01 | 用目标中文输入法连续拼音、选词、切换中英文，保存恰好在选词期间完成 | composition 和候选不被保存回执打断，无重复、跳字、光标回头 |
| D02 | 组合输入期间旋转 / 切应用 / 回来 | 无崩溃、正文不被旧磁盘内容覆盖；候选无法恢复时不能伪造已最终上屏 |
| D03 | emoji / 组合字符附近选区、删除、复制粘贴 | 不拆成非法 UTF-8，不在保存时替换为问号 / 替代字符 |
| D04 | 中文输入、长段粘贴后会话内撤销 / 重做 | 按编辑动作还原，自动保存不污染撤销历史；结果能正确保存 |
| D05 | 键盘开合、长按菜单、滚到文末、继续输入 | 当前输入行可见，不出现两层滚动抢手势；系统返回先收键盘 |
| D06 | 系统字体 100% / 200%、TalkBack、深浅色、旋转 | 必要操作与保存状态可辨认、可操作，字号放大不遮住编辑正文与错误入口 |
| D07 | 达到两个支持上限附近，粘贴一次超限文本 | 整次拒绝且说明原因，保留原正文、合法选区与组合状态；不截取部分保存 |
| D08 | 打开超过支持上限的测试正文 | 保护原文件，不以截断数据打开后自动回写；压力测试可失败但不能破坏文件 |

输入舒适度必须由用户在目标真机实际试用；当前输入法观测见设备约定。模拟器键盘输入不构成真实中文输入法验收，有真机时不额外跑模拟器补测。

## E. 长文、时序与性能基线

所有耗时指标都是**待验证目标**，文稿规模基线已经用户确定。按设备约定选择真机；每档记录模型、API、输入法、构建类型、样本数和测量方式，不能从桌面模拟器推导真机结果。

| 项目 | 初始目标与判定方式 |
| --- | --- |
| 支持文稿 | 同时满足 10 万码点与 1 MiB；至少含大量短段、单个长段、中文 + emoji 三种分布 |
| 打开正文 | 至少 20 次重开样本，p95 从发起打开到可编辑 ≤ 2 s；应用冷启动另行记录，不混作同一指标 |
| 一次完整提交 | 至少 30 次覆盖长文中间 / 文末修改，p95 ≤ 1 s；包含 previous、sync、主提交与回读 |
| 自动保存状态时延 | 停止输入通常 ≤ 1.5 s；连续输入最早未覆盖修改通常 ≤ 3 s；关联具体版本和调度时间确认，不能只看动画 |
| 输入响应 | 真机输入到更新的 p95 目标 ≤ 100 ms；至少 100 次交互并记录测量方法。若暂无法可靠量化，标“未测”，不能仅凭录屏主观宣称达标 |
| 卡顿 / 内存 | 无 ANR / OOM / 明显冻结，保存时可继续输入；说明是否因全文快照造成尖峰，不能每键积累历史快照 |
| 超范围压力 | 100 万码点只观察打开拒绝、内存和无数据破坏，不承诺编辑响应指标 |

若当前文本控件在这些基线上失败，先明确失败原因和后续替代验证；不能将支持范围静默改小或以增加线程掩盖主线程大拷贝问题。

## F. 最小 `.txt` 导出（首片必过）

| ID | 操作 | 必须结果 |
| --- | --- | --- |
| F01 | 在本地 Documents provider 导出普通、空白、中文 / emoji 文稿 | 字节与点击导出时捕获的规范化 UTF-8 快照完全一致；系统文件管理器和外部文本工具可读 |
| F02 | 导出 picker 打开后继续发生会话状态变化，或 picker 期间进程死亡 | 不悄悄改换导出内容；进程死亡后不假报完成，不依赖向 Bundle 塞全文保留任务 |
| F03 | 取消选择、重名、关闭流失败、provider 写入中断 | 取消不改主稿；重名不覆盖旧文件；失败不报成功，对可能留下的不完整副本如实提示 |
| F04 | 主存储保存失败时从内存导出 | 可尝试救出当前内容；导出成功不清除主存储失败、不把主稿标已保存 |
| F05 | 导出后继续编辑 | 导出状态不暗示持续同步，不把旧副本说成最新；不自动再次写回所选 URI |

云端传输可靠性和远程持久性不在本片验收范围，不把本地 provider 成功外推为云备份成功。导入 / 导出文字往返在 G 组验证。

## G. 本机文件导入副本（首片必过）

| ID | 操作 | 必须结果 |
| --- | --- | --- |
| G01 | 在目标真机选择普通 `.txt`、`.md` 和 0 字节文件 | 分别创建独立私有文稿，类型 / 名称正确；Markdown 按源码编辑，不依赖源文件写权限 |
| G02 | 记录源文件字节摘要，导入后编辑、自动保存、恢复、导出 | 源文件摘要完全不变；所有正文更改仅在私有副本 |
| G03 | 导入后移动 / 删除合成源文件或让来源授权失效，重启应用 | 私有副本仍完整可读可写；不能持续追踪源文件或要求重新授权才能打开副本 |
| G04 | 导入同名不同内容及再次显式导入同一源 | 每次独立 ID，不覆盖旧稿；显示上可区分，旧副本仍可从最小列表重新打开 |
| G05 | UTF-8 BOM、CRLF / CR、空行、制表符、emoji 与无末尾换行 | 仅去 BOM / 换行规范化，其他文字不变；导出后再导入，规范化正文相同 |
| G06 | GBK / UTF-16、非法 UTF-8、NUL / 明确二进制、超限文本、伪造 MIME | 明确拒绝，无替代字符“修好”、无截断导入，源与已有私有稿不变 |
| G07 | provider 返回未知 / 虚假大小，实际流超出 1 MiB 或解码超 10 万码点 | 实际有界读取与码点检查生效，不能无限读取或绕过限制；临界值合法文稿可读 |
| G08 | 读取中断、无权限、磁盘满、初始化同步 / 校验 / 发布前进程死亡 | 不将半文件加入正式文稿列表，不覆盖旧稿；错误可见，残片不成为空稿 |
| G09 | 新稿发布后、更新最近文稿指针前结束进程 | 重启扫描仍能找到完整新副本，不因指针未更新丢失已发布文稿 |
| G10 | 旧活动稿尚未保存时导入，或导入过程中又编辑旧稿 | 切换前保存最新旧稿；失败保留旧会话，不强制覆盖或离开；新副本若已发布仍可达 |
| G11 | 控制字符 / 路径分隔符文件名、损坏元数据 / 指向其他路径的 bodyFile | 显示名清理、私有 ID 独立；不写出指定目录、不读取越界文件，损坏稿有可见恢复入口 |
| G12 | 在两篇文稿间切换时故意延迟旧稿写入回执 | 文稿 ID、正文路径和 UI 状态不串稿，原来的单写者安全规则持续成立 |

源文件不变用合成文件前后完整摘要验证，不读取或改写用户原有私人文稿。

## H. 系统文件打开关联（首片必过）

| ID | 操作 | 必须结果 |
| --- | --- | --- |
| H01 | 真机文件管理器分别对 `.txt` / `.md` 选择“打开方式” | 兼容 MIME 下出现 Makudon 候选，选择后导入副本；记录实际发送方、MIME 与授权情况 |
| H02 | 应用关闭时打开，以及已有文稿时再次打开外部文件 | 冷 / 热入口都走相同导入与旧稿保护，不开启第二套独立 writer，不直接写源文件 |
| H03 | 导入请求经历 Activity 重建 / 恢复同一请求任务 | 同一任务不重复创建副本；用户再次主动打开同一源则允许创建新副本，不永久按 URI 去重 |
| H04 | 无 URI、无读取授权、非 content URI、未知 MIME 或伪装二进制 | 报告可理解失败，不探测全盘、不把传入路径用作私有路径、不破坏当前稿 |
| H05 | 发起方将 `.md` 错报为通用二进制，URI 不含扩展名 | 记录系统候选匹配限制；应用内导入仍可使用受控选择路径，不以注册任意文件类型掩盖兼容缺口 |
| H06 | 使用 `text/plain`、`text/markdown`、`text/x-markdown` 等来源分别打开 | 支持范围逐项验证；不把单次显式组件 adb 启动成功当作系统候选匹配已通过 |

真机系统已设其他默认应用时，通过系统提供的“打开方式”入口验证；不在测试中自动清除其他应用默认设置。全局 `*/*` / 泛化二进制关联不属于可接受的兼容修复。

## I. 调试设备策略（后续工具实现 / 执行约束）

| 状态 | 必须行为 |
| --- | --- |
| 一台真机；或真机与模拟器共存 | 只选择真机，Run / Screenshot / Logcat 使用同一真机 serial |
| 多台真机 | 遵循用户指定，否则请求选择；不取第一台或转向模拟器 |
| 真机未授权 / offline / 运行中断连 / 安装失败 | 说明并处理真机问题，不自动打开或转移到模拟器 |
| 确认无真机 | 允许复用配置 AVD |
| 用户明确要求模拟器 | 本次按指定范围执行，不改变长期真机优先约定 |

本轮只更新规则文档，尚未修改设备脚本；因此 I 组是 Agent 执行约束与未来自动选择功能的验收要求，不标为脚本测试已通过。

## 完成门槛

1. D1 / D2 / D3 已由用户确定；实际真机验收仍须执行，连接状态或 ADB 属性读取不等于应用功能通过。
2. 保存调度 / 并发 / 错误策略的 JVM 行为测试和必要 Android 文件边界 / 进程测试通过。
3. `Check` 通过，按设备约定选择的目标 `Run` 通过，A–H 适用用例均有实际证据，执行遵循 I 组约束。
4. 不留下正文日志、调试故障入口或破坏性自动清数据逻辑；用户亲自完成中文和长文试用。
5. 更新状态与已接受 ADR，明确支持范围、限制和仍未验证事项；没有“文档已有设计，所以功能已完成”的状态跳跃。
