# ADR 0003：目录索引发布与原生排版编辑边界

- 日期：2026-10-25
- 状态：接受并已实施，验证与限制见任务 0008。
- 依据：用户明确要求按工作区例图直接制作应用，并指定模拟器测试；范围已包含目录操作与 Markdown 双视图，不再限于原先的最小纯文本切片。
- 不取代 [ADR 0002](0002-document-storage.md) 的私有主存储 / 独立导入副本决定。

## 决定

继续单模块 Compose，以进程持有的 ViewModel 管理唯一活动编辑器；Activity 重建及 singleTask 外部 VIEW Intent 共用这个所有者。UI 不操作磁盘，全部文件操作使用 IO dispatcher、同一 Mutex 和不可取消的在途事务；未开始的保存只保留最新快照。

工作区位于 `filesDir/workspace/`：

```text
catalog.properties               schema 1，节点 ID / 名称 / parent / kind / created / opened、主题和排序偏好
documents/<uuid>/body.txt         或 body.md，标准 UTF-8 正文
documents/<uuid>/previous.txt     最近一次不同正文提交前的完整版本
documents/<uuid>/body.txt.new     仅为未发布事务材料，不自动当正文
recovery/<uuid>/                  用户显式恢复前保存的原始现场
```

目录功能需要一个可原子发布的权威元数据索引，采用标准 Properties，避免新增数据库或序列化运行库。索引不包含正文或源 URI。节点 ID、类型、父目录、名称冲突与环均在发布前校验，正文路径只能从经验证的 UUID 与类型推导。普通自动保存不改目录元数据；修改时间和摘要从正文读取，不把索引时间当保存成功证明。

排序关闭“文件夹优先”时仍使用一致的键，避免文件 / 文件夹混排违反比较器传递性。文件夹修改时间为自身创建时间与后代内容 / 创建时间的最大值，大小排序使用无正文的 0 键；这些值不代表外部文件系统目录属性。普通文件夹优先分组内继续自然名称排序。界面摘要折叠空白，正文保持原样。

外部 VIEW 发布时把请求 ID 与文稿一起提交，另外保留单 Activity 最新已处理请求 ID；即使用户删除该导入稿，旧任务恢复也不能重新导入。用户再次主动打开会生成新请求，可建立独立副本。目录索引的写入结果不确定或重新读取失败时清空存储层的可写状态，必须重读验证成功后才接受后续变更。

新建 / 复制先建立独立正文、sync 并回读，再原子发布索引。发布前中断留下的私有材料不进入列表，也不自动覆盖 / 清除。发布后的文稿以目录索引可达，无单独“最近指针”成为唯一入口。损坏或缺失索引存在其他材料时停止初始化，不能用默认空工作区覆盖。索引的备份 / 重建工具尚未提供。

逻辑移动与重命名只改索引，保留正文 ID。删除先确认范围，再原子发布移除后的索引，之后清理对应私有正文。进程中断时残留文件不会被扫描重新加入目录；若清理失败，明确提示“已移出目录但清理未完成”。这不是用户可用回收站，也不承诺撤销删除；残留清理和恢复材料的完整维护工具仍需后续设计。

原子写采用同目录 `.new`、显式 `FileDescriptor.sync()`、完整回读、`Files.move(ATOMIC_MOVE, REPLACE_EXISTING)` 及主文件完整回读。API 26 起具备所需 NIO API；不支持原子移动或结果不确定时返回失败，不降级为截断覆盖。采用此封装便于 JVM 故障测试，也能显式检查同步错误；平台 AtomicFile 的 `finishWrite` 内部存在只记日志的错误路径，不能单凭返回认定保存成功。依据：[AtomicFile 官方实现](https://android.googlesource.com/platform/frameworks/base/+/HEAD/core/java/android/util/AtomicFile.java)、[Android Files API](https://developer.android.com/reference/java/nio/file/Files)。不承诺突然断电、目录项 fsync 或介质故障的零丢失。

## 编辑与保存

源码使用稳定的 `BasicTextField(state)` / TextFieldState，选区和 composition 留在进程编辑状态；Bundle 不保存正文。保存协调器独立观察文本，500ms 停顿 / 最长 2s 调度；旧版本回执不改正文、不确认新版本，失败暂停自动重试。离开前同步捕获最后输入并等待最新提交，后台尽力提交。

排版先支持一级 / 二级标题和普通段落。每个可见段落保留自己的原生 IME 缓冲，更新明确源码范围，其后范围按长度差平移；不重建整篇 Markdown、不改分隔空行。段内新增空行在当前编辑段落内保留，重新进入排版时再解析。复杂语法原样展示并提供切回源码编辑。段落输入、模式切换、后台和离开均同步最新缓冲，避免最后一次输入仅停留在 Compose 副作用中。

源码与排版共享有界撤销差量（至多 100 项、累计约 4 MiB UTF-16 内容），不为每次按键保存整篇历史；进程死亡不恢复撤销。跨段落连续选择、完整 Markdown 富文本与严格光标映射尚非该实现的能力，源码可编辑全部内容；不得宣称完整所见即所得。

## 代价与验证

完整 Noto Sans SC 可变字体约 16.95 MiB，单一资源提供 450 / 500，不使用设计例文子集。保留标准字符及缺字回退，字体切换只留角色边界。新增 ViewModel / 协程显式依赖复用现有传递依赖，不引入 DI、导航库、数据库或 Markdown 运行库；虚拟时钟库只用于 JVM 测试。

测试覆盖存储冲突、原子提交失败、并发保存、Unicode、目录操作及模拟器实际交互。完整真机输入法、性能 p95、断电 / 所有进程中断阶段和多 provider 兼容性仍需后续验收，不能把正常模拟器通过等同于全部首片验收完成。
