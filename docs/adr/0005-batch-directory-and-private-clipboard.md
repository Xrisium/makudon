# ADR 0005：目录批量事务与统一私有剪贴板

- 日期：2026-10-26
- 状态：接受并实施，验证见任务 0014。
- 依据：用户确认任务 0013 的原生复选和统一剪贴板方案并授权实现。
- 关联：扩展 ADR 0003 的目录操作范围，保留 schema 1、私有正文和既有原子索引格式；不迁移或重写已有文稿。

## 操作与数据边界

以稳定 ID 选择，根目录不可作为操作项；选中文件夹即代表整个子树，规范化后只保留最上层操作根。子项继承勾选，部分后代单独选中时父级为半选。新建目标与复选集合独立，清空勾选不退出，界面退出由 X 控制；模式内屏蔽主标签滑动与底部导航。

单项菜单和复选底栏共用同一份进程私有剪贴板。复制保存独立正文快照，重复粘贴创建独立 UUID / 正文，不因源删除失效；剪切只保存源 ID，粘贴成功后才清空，失败 / 取消保留。退出复选、清空勾选和 Activity 重建保留剪贴板，进程死亡不恢复剪贴板或待执行操作，不接触系统剪贴板。

复制快照的累计 UTF-8 正文上限为 8 MiB，避免一次递归复制耗尽内存；超限整次捕获失败，不替换旧剪贴板，原文稿不变，界面提示分批。每篇文稿原有 10 万码点 / 1 MiB 校验保留。索引在发布前检查既有读取边界（最多 10,000 个条目、编码后 4 MiB），避免成功写入下次无法读取的索引。

批量复制先规划全部名称、UUID 和正文并校验，完整写入 / sync / 回读所有新正文后一次发布索引。批内重名同样分配副本名。写正文中断不会发布部分副本，源不变；未发布的材料继续按 ADR 0003 留在私有目录，不静默清理。

批量移动在提交前检查全部 ID、目标、目录环与同名冲突，一次发布整个索引。已在目标目录的条目不改变，全部原位则拒绝为无需移动。任一冲突整批不发布，不能通过 UI 循环调用单项操作。

删除先确认去重后的名称 / 位置及真实递归范围，一次从索引移除全部对象，再尝试清理每篇被删文稿。一个清理失败不阻止其他清理，最后明确反馈清理未完成；界面更新为已发布的目录，清理失效勾选及剪切引用。没有回收站，不以残留材料承诺恢复。

全部存储仍由原 ViewModel 的 Mutex / IO dispatcher 与保存屏障协调。索引发布结果不确定时存储层失效，禁止继续发布，重读后再操作；不静默重试批量动作，不能保证断电或多文件跨介质的零丢失。

## 粘贴目标

文件夹菜单粘贴到自身，文稿菜单粘贴到所属目录。复选底栏把每个选中文稿映射到父目录、文件夹映射到自身，按目录 ID 归并；唯一目标预选并显示确认，跨目录 / 层级必须显式选择一个位置，初始不选任何目标。相关目录、共同上级和其他文件夹只是候选，不自动向多处重复粘贴。零选择使用原新建位置作为建议。

确认页分开展示剪贴板来源和目标，禁用自身 / 后代、失效目录、移动重名与全部原位等无效选项。请求绑定剪贴板版本，避免旧确认意外操作后来的剪贴板；执行前仍由存储层完整复核，界面禁用不作为数据安全边界。
