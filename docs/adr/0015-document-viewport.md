# ADR 0015：独立保存文稿视口位置

- 日期：2026-11-16
- 状态：接受并实施

## 背景与约束

阅读和编辑都会改变用户的停留位置。恢复光标会把阅读进度带回旧的输入位置；只存滚动像素则不适合跨视图、字号、行距与窗口变化。位置记录须静默进行，不改正文、修改时间或 ZIP 协议。

## 考虑的方案

1. 只保存光标或整篇百分比。
2. 每次滚动更新目录索引。
3. 将源码锚点与局部偏移作为可丢弃的独立本地元数据。

## 决定与理由

采用第三项。纯文本记录视口首行的源码偏移，Markdown 记录首个可见源码块及块内像素偏移；附带当时行高和视图模式。恢复时定位源码锚点，并按当前 / 原行高比例换算局部偏移，越界时限于有效文稿和滚动范围。纯文本编辑 / 阅读共用连续正文与滚动状态；Markdown 沿用源码 / 排版 / 阅读的源码块映射。

元数据保存在当前库代际的 `positions/<文稿 ID>.properties`，由 WorkspaceStore 校验 ID 和条目存在性。使用现有 AtomicDisk 和 IO 互斥，停留 450ms 合并记录；离开文稿和进入后台尽力提交。写入捕获原 store 和文稿 ID，迟到回调不能写入新库 / 新文稿。无正文、路径或通知日志，不进入 ZIP，不更新最近修改时间；不持久化选区与撤销历史。

元数据缺失、损坏、超限或写入失败不阻止打开与保存正文，也不冒充正文保存成功。下次有效滚动 / 离开仍可重试。其可靠性与正文自动保存分开，进程在记录前被杀可能恢复到更早的停留位置。

## 代价、迁移与回退

不迁移正文或目录 schema，旧库无位置时从顶部打开。像素偏移按行高换算能够保持附近位置，但 Markdown 不同视图的段落间距、图片和表格高度不同，不承诺逐像素一致。删除位置文件只会丢失接续位置；回退版本忽略这些文件。库代际切换不共享位置；文稿重命名 / 移动保留原 ID 的位置，新副本使用独立 ID。

## 验证依据

位置元数据的重开、正文 / 索引不变、文稿 / 代际隔离、非法 / 超限材料及写入失败由 JVM 用例覆盖；模拟器验证见[任务 0042](../tasks/0042-reading-and-long-document-navigation.md)。
