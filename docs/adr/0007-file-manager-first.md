# ADR 0007：文件管理器优先的文件交互

- 日期：2026-10-31
- 状态：接受并实施；实测范围以验收记录为准
- 背景：用户希望国内品牌机使用熟悉的自带文件管理器。SAF 选择器与桌面文件管理器可能不是同一组件；选择文件和保存文件也不是同一种协议。

## 决定

1. 应用内文稿和 ZIP 导入先显示实际处理应用，由用户每次选择；使用 GET_CONTENT / OPENABLE，华为已发现的文件管理包置前，组件动态查询。另保留 OPEN_DOCUMENT 系统入口，不用厂商私有 Action 或修改系统默认。
2. TXT 和 ZIP 导出共用固定快照、分享、下载目录及 CREATE_DOCUMENT 出口。导出文件名随正文 / ZIP 一起冻结；取消外部选择器或写入失败仍可用同一份副本重试，关闭导出面板结束当前任务。
3. FileProvider 仅开放 files/shared-exports。每次导出使用独立目录，至少保留 24 小时；下次准备时清理到期的非活动副本。采用 filesDir 而非 cacheDir，避免缓存回收提前破坏接收方读取；这不是版本历史或独立备份。清数据 / 卸载仍会丢失。
4. 分享只授予临时读取权限，不把 Activity 启动或返回视作本地保存成功。厂商声明 SEND 只证明可以接收，不能证明可以保存到本地；未经验证的华为入口显示“通过文件管理分享”。
5. API 29+ 通过 MediaStore.Downloads 新建文件至 Download/Makudon；同名不覆盖，pending 写入、回读校验后发布，失败删除未发布条目，清理失败明确提示。API 26–28 保留分享 / SAF，不申请存储权限。
6. 正文私有权威、副本导入、源 URI 只读、UTF-8 / 容量 / ZIP 校验及保存屏障保持不变。不把 URI 转换成真实路径，不新增广泛存储、网络或所有应用查询权限。

## 影响与验证边界

- 替代导入协议原先“默认只打开系统 OPEN_DOCUMENT”与首片“仅 CREATE_DOCUMENT 导出”的交互限制；不改变文件内容协议。
- Android 状态不含正文。Activity 重建复用进程内请求 / 导出；进程死亡后不盲目使用迟到结果，提示重新发起。
- 其他品牌只提供动态候选，不宣称经过真机适配。华为能力检查和交互结果见当轮验收记录。
- FileProvider 使用现有 AndroidX Core 传递依赖，无新增运行库；Manifest 只增加匹配 GET_CONTENT / SEND 的 queries。
