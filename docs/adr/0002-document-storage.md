# ADR 0002：首个编辑切片的正文存储

- 日期：2026-10-24
- 状态：**接受**（2026-10-24，用户选择私有目录、导入副本、文件关联与最小 `.txt` 导出）
- 关联：[设计方案](../specs/0001-plain-text-editor.md)、[决定记录 D1 / D2](../specs/0001-open-decisions.md)、[导入与文件关联](../specs/0002-import-and-file-association.md)

## 背景与约束

首片需要证明单篇纯文本可以舒适输入、可靠保存、失败后可恢复。用户长期希望文稿易导出、无需服务器，也可能由其他应用访问；当前并无导入导出功能。工程默认禁用系统自动备份，不可把应用内保存当作独立备份。

## 考虑的方案

这里的“私有目录”专指内部持久目录 `filesDir`，不是缓存或外置的 app-specific 目录。SAF 是系统文档访问框架，实际数据可能位于本机 Documents、SD 卡或云盘 provider。

| 比较项 | 应用内部私有目录 | SAF 文件 / 目录作为主存储 |
| --- | --- | --- |
| 首次使用 | 直接创建草稿，无系统文件授权 | 系统选择文件或目录，需要处理取消、只读等状态 |
| 访问权限 | 无存储权限；其他普通应用不能直接读写 | 无广泛存储权限；依赖选中文档的 URI 授权，重启后访问需要取得持久授权，移动/删除仍会失效 |
| 覆盖保存 | 应用控制本地文件，可采用临时文件和原子替换 | provider 能力不同；不能普遍假设随机写、截断、原子替换或重命名可用 |
| 失败与并发 | 主要处理本地 I/O、进程中断、容量不足；普通外部应用不会并发改写正文 | 另需处理 provider 不可用、介质移除、网络/同步延迟和其他应用改写 |
| 卸载 / 清数据 | 私有文稿被删除，必须事先导出 | 普通用户文档不随应用卸载删除；原应用的访问授权不能据此假定仍在 |
| 文件管理器 / 电脑编辑 | 需要显式导出 | 通常更方便，但取决于所选 provider 和位置 |
| 本地运行 | 不依赖 provider 或网络 | 选择本地 provider 可以离线；选择云盘不能视为纯本地，也不代表应用已实现同步 |
| 首片成本 | 较低，可集中验证输入与保存 | 较高，需要本地恢复副本、外部冲突检测及更多错误状态 |

权限与卸载行为依据 [私有文件](https://developer.android.com/training/data-storage/app-specific) 和 [SAF 官方指南](https://developer.android.com/training/data-storage/shared/documents-files)。provider 能力应查询 flags，持久 URI 授权也不能防止文档移动/删除导致失效；“不能普遍原子替换”是基于这些能力差异作出的设计约束。

## 决定及理由

**首片以私有目录作为唯一权威正文；通过 SAF 导入本机文件副本并导出 `.txt` 副本。** 用户同时要求 Makudon 成为纯文本 / `.md` 的系统“打开方式”候选，关联打开也只导入副本。

每篇文稿有独立权威正文与有限本地恢复副本；不维护私有 / SAF 两份持续双向同步的“主文件”。最小 `.txt` 导出已纳入首片。每次导入创建独立文稿，不覆盖当前或同名旧稿；已有文稿必须能重新打开。

该选择以可控保存换取显式导入 / 导出操作；源文件与私有副本后续互不跟随修改。用户已接受这种副本模式。未来若转向原文件持续编辑，应另立 ADR，不能作为一次内部重构悄悄改变语义。

## 未采用的 SAF 主存储方案（保留比较依据）

1. 首先限定为**单个本地文档**，通过 `ACTION_OPEN_DOCUMENT` / `ACTION_CREATE_DOCUMENT` 获得所需权限；不同时加入目录树、云盘和多文稿管理。
2. 私有目录仍保留最近本地恢复快照；区分“本地草稿已保护”和“外部文件已写入”，不能用一个“已保存”混淆两者。
3. 打开时记录读到的基线；写回前检测外部变化。大小、修改时间只能提示，不能作为可靠版本标识；内容摘要也不能消除读写间竞争，SAF 没有通用 compare-and-swap 事务。
4. 若 provider 无法给出安全覆盖语义，优先“另存副本”；不能悄悄截断原文件，不能把私有文件的提交算法直接套在 URI 上。
5. 权限失效、provider 离线、外部修改或写入不完整时保留私有恢复稿，提示重新授权 / 另存副本，暂停自动写回。

这会增加权限、冲突和外部结果不确定的验收，已选私有目录方案不覆盖这些原文件持续编辑情形。

## 代价、迁移与回退

- 私有文稿及本地恢复副本会一起受卸载、清数据和设备损坏影响；它们不是异地备份。
- 开发包和正式包隔离，未来迁移需显式导出 / 导入，不能修改 applicationId 后假定数据仍在。
- 设计中的正文为标准 UTF-8 `.txt` / `.md`，不把正文嵌入数据库或专有 JSON；每篇使用独立 ID 和少量元数据，最小列表保证已导入文稿可达。这些结构尚未实现。
- 未来更换主存储必须先复制、验证和由用户确认结果；不能以“迁移”为由直接删私有原稿。
- ADR 已接受代表需求与设计方向明确；本轮仍仅更新文档，不授权代码实现。目录树、同步、ZIP 和 Markdown 渲染仍未纳入本片。
