# 产品约定

## 已知需求

来源：用户在参考会话《推荐技术栈路线图》中的明确描述，以及 2026-10-24 的初始化、设计选择与补充要求。

- 项目名 Makudon，开源，以个人使用为主。
- Android 上编辑 Markdown 与普通文本，覆盖知识/学习笔记、旅行日记、同人文、小说。
- 优先轻量、舒适编辑阅读、简单目录；不做 Obsidian 竞品或复杂知识库。
- 尽可能本地运行；弱同步/备份首先考虑导出文件或 ZIP，不要求自建服务器、付费同步服务。
- 已确定私有目录保存权威正文；本机纯文本 / `.md` 文件可导入为独立私有副本，后续修改不写回源文件。
- Makudon 注册为纯文本 / `.md` 的系统“打开方式”候选；关联打开也采用导入副本语义，不是直接编辑原文件。
- 首片包含最小 `.txt` 导出；文稿基线同时为 10 万 Unicode 码点与 UTF-8 ≤ 1 MiB。
- 由 Codex 主导开发，用户在 VS Code 阅读修改，并频繁通过模拟器/真机验收。
- 默认调试**有真机连接时仅用真机，无真机才用模拟器**；用户主动指定时按要求。真机授权 / 运行异常不构成自动切换模拟器的理由，见 [设备约定](device-policy.md)。
- 视觉简约柔和，有日系的温暖轻松感，避免直白的猫爪、樱花等图案；白底黑色线条图标。
- 2026-10-24 补充视觉方向：Soft Minimalism、黑白为主、低饱和多主题与深色、圆角和平滑动效；UI 使用 Noto Sans 系列 500、正文当前试用 450（不可用则 400），预留独立字体切换。Fredoka Semibold 仅生成路径字标，Lucide 作为 UI 图标来源。具体方案与未定参数见 [设计原则](design.md)，不代表功能已经实现。
- 已选择柔和卡片；“目录 / 最近 / 设置”三标签，默认最近；最近无标题口号、不显示扩展名，右上角新建按钮取代“本机”，进入纯文本 / Markdown / 导入的新建二级页，不再显示新建卡片。正常编辑全自动保存；Markdown 源码与排版后的视图均应可编辑，名称待确认。目录新建位置、收件箱默认方案和双视图边界见 [界面设计](specs/0003-workspace-and-markdown-views.md)，完整目录与双视图尚未实现，不自动扩展首片实施范围。
- 2026-10-25 补充：目录工具栏增加名称搜索与创建目录，顶部提示替代新建位置卡片；展开 / 收起和各类排序具有图标差分，排序菜单需与主题统一。Markdown 类型标识采用 Fluent Markdown 20 Filled，其余操作图标继续用 Lucide；[来源和许可](third-party-assets.md)已记录。

## 当前不做

账户体系、自动多端同步、冲突合并、插件、双向链接、图谱、复杂标签、协作编辑、订阅服务、AI 写作、WebView 编辑器、跨平台共享框架。

导出不是自动同步；未来若用系统文件选择器连接第三方云盘，上传可靠性与冲突仍需要单独设计。

## 已确定方向与尚待验证项

- 私有主存储、导入副本、文件关联和最小导出已定案，见 [ADR 0002](adr/0002-document-storage.md) 与 [决定记录](specs/0001-open-decisions.md)；功能尚未实现。
- 长文输入法组合、撤销、选区、滚动和性能是否适合现有 Compose 文本输入组件，尚待实现与实测。[首片设计与性能目标](specs/0001-plain-text-editor.md) 采用已确定基线；已识别真机记录在 [设备约定](device-policy.md)。
- `.txt` / `.md` 在真实文件管理器中的 MIME 与“打开方式”兼容性、UTF-8 导入和原文件不变行为尚待验证，见 [导入设计](specs/0002-import-and-file-association.md)。
- Markdown 源码 / 排版双视图编辑引擎、支持语法范围、源码映射保真、撤销与相对图片策略尚未选择 / 验证；当前整体需求不再是只读预览。
- 最低 Android 版本暂为 API 26，以现有样例为起点；正式支持范围需结合用户真机决定。
