# 任务：卡片导航与双视图编辑设计

- 状态：完成（设计草案与交互示例；默认位置和模式命名待用户反馈）
- 用户目标与范围：延续视觉讨论，采用柔和卡片、试用正文 450；展示目录 / 最近 / 设置、新建文稿二级页、自动保存和可编辑的 Markdown 双视图；讨论新建位置及视图命名。依 Git 约定提交工作区改动。
- 不在范围：Android 功能实现、目录数据迁移、Markdown 编辑引擎选型、设备操作、APK 交付或 push。
- 相关规范：[设计](../design.md)、[首片](../specs/0001-plain-text-editor.md)、[数据安全](../data-safety.md)、[Git](../git-workflow.md)。

## 验收条件

- 默认进入最近，无原先标题口号；首卡进入三选项新建页，最近列表不显示扩展名。
- 目录树支持展开 / 折叠、选择目标、新建入口与常见排序；从目录进入新建页保留明确目标，从最近默认进入收件箱（建议方案）。
- 正文使用真实可变字体 450，保留 400 / 500 对照与独立 UI 500。
- 无常规手动保存按钮，保留自动保存状态、失败重试与导出出口。
- Markdown 示例可在源码 / 排版中局部编辑和切换，文字不随无修改切换而丢失；明确仅为有限语法、内存中的交互示例。
- 同步当前文档中的冲突说明，分清用户明确要求、建议和首片范围；按文件审查、细粒度提交，不 push。

## 实施步骤

1. 核对规范、已有改动、字体轴与目录参考。
2. 制作新交互例图并检验导航、位置、排序、双视图及字体。
3. 同步设计与自动保存约定，审查并分类提交设计素材、文档及现有 Git 约定调整。

## 验证与交接

- 交付新版柔和卡片例图：默认最近、三标签、新建首卡 / 三选项二级页、目录树 / 排序 / 上下文新建、可更改的存放位置、源码 / 排版局部编辑与全自动保存状态示例。
- 字体：直接检查 Noto Sans SC 原文件的可变轴为 100–900；例图设计子集保留 400–500，可真实使用 450，UI 继续 500。子集仍不得作为正式编辑器字体。
- 浏览器验证：Chrome 无头模式检查三个标签、新建 / 导入目标、目录折叠、五类排序与升降序 / 文件夹优先、默认最近与隐藏扩展名、无手动保存按钮、源码切换原文保持、标题修改回映、保存状态与失败阻止离开、400 / 450 / 500 和五主题，未见脚本异常。
- 布局：外层 736 / 390 / 320px 的编辑页无横向溢出；288px 实际内容宽度下，最近、目录、排序面板、新建页、位置选择和设置的可见元素均处于手机容器内。人工查看最近 / 目录 / 新建 / 双视图 / 失败 / 设置截图；窄屏可触控件至少 48px。
- 设计控件检查：注册主题、字重、字号、行高与保存状态，450 与失败示例可更新。输入正文未进入宿主预览状态；模拟保存不代表磁盘持久化。
- 文档同步：新增整体导航与双视图设计；更新首片与验收中的默认入口、取消常规手动保存、保留自动保存竞态与失败保护；未选 Android Markdown 引擎，未改 ADR 私有权威正文。
- 本轮仅文档和品牌 SVG；不修改 Android / 构建，不运行 Check / Run，无设备操作、新 APK 或真实文稿迁移。中间检查脚本与截图在忽略的 `.local/`，预览在本对话 visualization 目录。
- Git：按文件审查后分类提交现有 Git 约定、品牌与素材许可、视觉及编辑协议文档；不执行 push。
- 检查说明：上游两份 OFL 原文各自含一处行尾空白，完整许可按来源字节保留以维持哈希；不修改第三方原文来通过格式检查。项目自身文档的差异空白检查与本地链接检查通过。
- 限制：排版只演示普通段落及一级 / 二级标题，其他结构保留为源码片段；真实引擎保真、组合输入、撤销、跨块编辑、持久化与 Android 无障碍均未验证。
