# 设备选择与调试约定

- 生效日期：2026-10-26，取代此前真机优先的规则。
- 来源：用户明确要求 Agent 会话测试优先使用模拟器，完成后向真机推送覆盖安装；一般不允许直接通过数据线调试真机，除非用户要求。
- 适用范围：安装、运行验收、截图、Logcat 和 instrumentation / UI 测试；编译、JVM 测试与静态检查不需要设备。

## 日常测试与最终交付

| 场景 | 默认行为 |
| --- | --- |
| Agent 开发与自动化回归 | 使用配置 AVD，优先复用；即使真机在线也不改变目标 |
| 模拟器不可用 | 处理现有 AVD，不自动安装新环境，也不转向真机数据线调试 |
| 本地检查与模拟器验收完成 | 重新识别连接设备，集中向测试真机覆盖安装应用 APK 一次，交给用户人工测试 |
| 唯一在线且已授权的测试真机 | 直接选它并显式传序列号，仅单向推送 APK 并发起覆盖安装；随后即完成交付子任务 |
| 多台在线真机且未指定目标 | 请用户选择，不随意取第一台 |
| 真机 unauthorized / offline 或交付失败 | 记录并处理连接问题，交付记为未完成；不反复安装或开展交互调试 |
| 本轮用户要求或任务确有必须进行真机调试的原因 | 按必要范围执行，并说明必须调试的原因；指定设备本身不代表要求调试 |

每轮设备操作前执行 `Devices` / `adb devices -l`，不要沿用旧序列号；完整真机序列号只用于命令或被忽略的本地记录，不写共享文档。除非本轮用户要求或任务确有必须进行真机调试的原因，不在真机执行截图、Logcat、instrumentation、自动点击、故障注入或性能调试。

真机覆盖安装默认为单向交付：APK 推送并发起安装后，即视为 Agent 已完成该子任务，不再询问用户是否安装完成，不轮询安装结果，不默认启动应用、查询进程或等待手机端安全确认。手机上的安装确认由用户自行处理，不作为 Agent 收尾的前置条件。若推送 / 安装命令本身明确报错，须如实说明，不能将失败记录为成功，也不能据此反复安装。交付记录使用“已推送 APK 并发起覆盖安装”，只有实际取得成功回执时才写“安装成功”；两者均不代表真机人工验收通过。

## 安装频率与测试数据

- 先集中完成代码、构建、Check、差异审查与模拟器测试，再合并安排最终真机交付。禁止在真机频繁、反复安装应用 APK 和测试 APK。
- 已安装版本能复用时直接复用；额外真机安装须说明原因和影响并获用户明确授权，完成标准不构成反复安装的授权。
- 用户叫停后，本轮不再安装，也不得改用模拟器安装绕过；可继续本地检查。若用户仅限制真机而明确允许模拟器，则按明确范围执行。
- 连接的测试真机仅供本软件人工测试，不用于生产或日常使用。可按新功能测试需要覆盖、重建或重置本软件文稿文件与目录树，无需逐次确认；可用独立合成测试集替换旧测试内容，并记录是否实际重置。
- 数据授权仅限已识别测试设备上 Makudon 开发包的文稿与目录，不能修改其他应用、用户源 URI 或整机资料；不默认卸载应用、清除全部应用设置或 wipe AVD。
- 通常仍用 `install -r` 保留数据，重置文稿是允许项，不是每次交付必做项。产品的保存失败保护、重命名冲突和删除确认仍须验证，不能因测试数据可重置而放宽产品行为。
- 覆盖安装会重启开发应用，交付前提示。真机输入法、无障碍与性能由用户人工验收，模拟器通过不等同真机通过。

## 当前脚本能力

无 `-Serial` 的 Run / Screenshot / Logcat 与双击入口、`Ctrl+Shift+B` 选择配置 AVD，符合日常测试优先模拟器的流程，不会自动转向手机。`Run -Serial` 还会启动并检查应用进程，默认单向交付不使用此路径；仅在需要真机调试时使用。最终交付复用已构建并验证的 APK，显式传本次识别的真机序列号：

```powershell
pwsh -NoProfile -File scripts/android.ps1 -Action Devices
# 日常模拟器测试
pwsh -NoProfile -File scripts/android.ps1 -Action Run
# 最终真机交付：仅推送并发起覆盖安装，不追加启动 / 进程检查
& "$env:USERPROFILE\DevTools\Android\Sdk\platform-tools\adb.exe" -s YOUR_SERIAL install -r app/build/outputs/apk/debug/app-debug.apk
```

VS Code 的 `Makudon: Run on selected device` 与 `test-android.cmd -Serial YOUR_SERIAL` 同样支持显式目标，但包含启动与检查，不作为默认单向交付入口。直接调用 adb 不会更新 `.local/last-run.json`，应在交付记录写明 APK 身份、设备型号与已发起推送安装的事实；不能引用旧安装记录冒充本次结果。此次仅调整流程文档，不修改脚本逻辑。
